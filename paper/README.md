# IEEE paper: LaTeX source (Overleaf-ready)

*From Flat to Micro-Segmented: A Simulation-Based Evaluation of Lateral-Movement Containment for Compromised IoMT Devices in a Smart-Hospital Network*

## Template source
The paper follows the IEEE conference template in `../IEEE_Conference_Template__1_.zip` (`conference_101719.tex`, `IEEEtran.cls`, `IEEEtran_HOWTO.pdf`, `fig1.png`, `conference_101719.pdf`), added on 2026-11-05. `main.tex` uses the template's class options, its package list, its title, `\thanks` and author-block layout, and its unnumbered *Acknowledgment* component head (left commented out until the authors write it). It also follows the template rule of no symbols, special characters, footnotes or math in the title and abstract. The template's `IEEEtran.cls` is byte-identical to the copy in this folder (SHA-256 below), so the layout is exactly the template's.

Deliberate differences from the sample file. None of them changes the prescribed page layout.
- References use BibTeX with `IEEEtran.bst` instead of a hand-written `thebibliography`. The output is the same IEEE reference style, and the `.bib` file must be submitted with the source.
- Tables use `booktabs` rules instead of the sample's `\hline` grid. The sample table only illustrates the format; table heads are still above the tables, and figure captions below the figures.
- Four packages are added: `fontenc` (T1), `booktabs`, `url` and `balance`.
- Before submission, check the venue's page limit, and remove every `TODO(authors)` (`python check_tex.py --todos`).

The template zip has no `IEEEtran.bst`. The BibTeX style (and, originally, the class) was downloaded from CTAN on 2026-11-04:

Overleaf also ships IEEEtran, so the bundled copies only pin the version. The document uses `\documentclass[conference]{IEEEtran}`.

## Layout
```
paper/
  main.tex              preamble, title/authors, \input of every section
  sections/             abstract, introduction, related, methodology, results,
                        discussion, limitations, conclusion  (.tex)
  tables/               AUTO-GENERATED by gen_tables.py, do not edit by hand
  figures/              copied from ../report/figures by build.ps1
  refs.bib              verified standards/vendor docs + merged research papers
  gen_tables.py         results/*.csv + configs/ -> tables/*.tex (+ numbers.tex macros)
  merge_refs.py         research/papers/refs.bib -> merged block in refs.bib
  check_tex.py          static LaTeX check (braces, environments, \input, \cite, figures, refs)
  tex2json.py           LaTeX source -> build/paper.json (same switches, numbers, numbering)
  build_docx.js         build/paper.json -> paper.docx (IEEE two-column Word version)
  build.ps1             runs the scripts, then compiles or writes overleaf.zip, then paper.docx
  IEEEtran.cls/.bst     template (see above)
```

## Build
```powershell
powershell -ExecutionPolicy Bypass -File paper\build.ps1
```
If `latexmk` or `pdflatex` is on PATH, the script compiles `main.pdf`. Otherwise it writes `paper/overleaf.zip`. Upload that on Overleaf with **New Project, then Upload Project**. Use the pdfLaTeX compiler (the default), and the main document is `main.tex`.

## Word version (`paper.docx`)
`build.ps1` ends by running `tex2json.py` and `node build_docx.js` (it needs `node_modules\docx`: `npm install docx@9.5.1 --ignore-scripts` in `paper\`). The Word file is generated from the same `.tex` sources, so it carries the same `\if` switches, the `numbers.tex` values, the "(expected, not yet measured)" notes, the section, table and figure numbering and the citation order as the PDF. Edit the LaTeX and rebuild; changes made by hand in `paper.docx` are lost on the next build.
- The layout follows the IEEE conference template: US Letter, two 3.5" columns, Times New Roman 10 pt, "TABLE I" captions above tables, "Fig. 1." captions below figures, booktabs-style rules and IEEEtran-style references. The full-width topology figure gets its own one-column section, so Word balances the columns above it. The PDF from LaTeX remains the reference layout.
- The template author block is shaded yellow until the names in `main.tex` are filled in.
- `tex2json.py` handles only the LaTeX this paper uses and exits with an error on any unknown macro or environment, so nothing is silently dropped. If you add a new macro, define it in `tables/numbers.tex` (zero arguments) or add it to `tex2json.py`.

## Data flow and the honesty rule
- `gen_tables.py` reads `results/config-complexity.csv`, `attack-matrix.csv`, `attack-surface.csv`, `functional.csv`, plus `results/static-analysis*.csv` if present, and the config files. It writes every table, plus `tables/numbers.tex`, the macros (`\cfgLinesDthree`, `\blockedDtwo`, `\hostsPctDthree`, ...) that the prose uses so text and tables never disagree.
- **When an `observed` column is empty, the table shows the `expected` value and its caption says *(expected, not yet measured)*.** With partly filled data, expected cells are marked with † and incompletely observed cells with ‡. `\ifmeasured` and `\expnote` switch the wording in the abstract, results, limitations and conclusion. Only `config-complexity.csv` is measured today.
- Attack outcome per design = majority vote over all locations × trials (ties go to the outcome worse for the defender). Attack surface = mean ± sample sd over all runs of a design.
- The figures in `figures/` are drawn by `tools/make_graphs.py` (outside this folder). After filling in observed data, run `python tools/make_graphs.py` and then `build.ps1`. The current PNGs are stamped "EXPECTED".
- If a `results/static-analysis*.csv` appears, a "Static policy analysis" subsection is switched on automatically (`\ifhavestatic`). For the `tools/policy_analyzer.py` format (`design,location,test_id,predicted,reason,expected`), the generator writes three things: a verdict matrix that stars every disagreement with the expected value, a list of per-run disagreements with the deciding ACL line, and, from `static-surface.csv`, a hosts/services table. Any other schema gets a truncated generic table. Static results are always labelled as analyser output, not Packet Tracer measurements. The analyser currently finds a D2 bypass: CORE-MLS accepts Telnet at 10.10.20.1, inside the permitted server zone. The prose discusses it.

## Length
With every table included, the draft is about 8 IEEE pages. Setting `\extratablesfalse` in `main.tex` drops the addressing, ACL-inventory and static-surface tables, along with the sentences that cite them. Cut the remaining prose to meet the venue's limit (target is about 6 pages).

## Citations
- `refs.bib` section 1 contains only standards and vendor documents I verified myself: every DOI resolved via doi.org and was checked against Crossref or the publisher page, and the Cisco/NetAcad URLs were fetched. Those documents are NIST SP 800-207, IEEE 802.1Q-2018, IEEE 802.1X-2020, RFCs 1918/2131/2328/3022/3046/4253/5424/5517/5905, the Cisco ASA 9.22 Access Rules guide and Cisco Packet Tracer.
- Section 2 is merged automatically from `research/papers/refs.bib` by `merge_refs.py` (re-runnable; it replaces the block between its BEGIN/END markers). The research agent collected and verified these entries. The merge sanitises them for pdflatex/BibTeX: it decodes HTML entities, escapes `&`, converts typographic dashes and quotes, normalises `month=July` to `jul`, and maps unsupported Unicode to ASCII. It prints every change it makes. Related Work cites only papers whose summaries in `research/papers/INDEX.md` were read, and each sentence states only what that summary supports. Many INDEX entries are "link only" (abstract-based summaries). The authors must read the closest papers in full.
- Where a claim still needs a source, the text has a `% TODO(cite): <topic>` comment instead of an invented key.
